# 06 - 定时计划与循环执行

> **适用版本**: v0.1.3+ | **目标读者**: 有自动化测试经验的测试工程师

---

## 概述

定时计划功能允许你设定在未来的某个时间点自动执行测试，无需人工值守。平台使用最小堆优先队列调度器 + node-cron 实现精确的定时触发。

**核心能力：**

- 单次定时执行：设定一个未来时间点
- 关联测试计划：自动执行指定的测试计划
- 循环执行：支持 1~999 次循环，可配置失败后是否继续
- 防系统休眠：可在执行期间禁止系统进入睡眠

---

## 调度架构

```
ScheduledPlanService (JSON 持久化)
    ↓
SchedulerService (最小堆优先队列 + node-cron)
    ↓
到期时 → 自动运行关联的测试计划
    ↓
IPC 通知渲染进程 (scheduled-test-start / scheduled-plan-expired)
```

---

## 整体流程

```
选择测试目录 → 创建测试计划 → 创建定时计划 → 等待自动执行 → 查看报告
```

> [!NOTE]
> 定时计划和测试计划是独立的实体。你先需要创建好测试计划，再将其关联到定时计划中。

---

## 步骤 1：前置条件

在创建定时计划之前，确保已完成：

1. **选择测试目录** — 在「测试执行」Tab 中选定含有测试脚本的目录
2. **创建测试计划** — 至少创建一个测试计划，包含测试文件、测试类型、循环设置

详见 [04 - 测试执行与报告](04-test-execution.md)。

---

## 步骤 2：创建定时计划

### 2.1 弹出定时计划弹窗

在「测试执行」Tab 左侧面板的「定时计划」区域，点击「新建定时」按钮。

### 2.2 配置定时参数

| 参数 | 说明 | 是否必填 |
|------|------|----------|
| **计划名称** | 定时计划的标识名称 | 是 |
| **执行时间** | 目标执行的日期和时间 | 是 |
| **选择测试计划** | 勾选到期时要执行的测试计划（支持多选） | 至少选一个 |

### 2.3 时间选择器

点击执行时间输入框，弹出日期时间选择器：

- 选择日期（日历视图）
- 选择时间（小时:分钟）
- 确认后时间格式化显示在输入框中

### 2.4 保存定时计划

点击「保存」，计划写入 `config/scheduled_plans.json`，SchedulerService 自动入队。

---

## 步骤 3：管理定时计划

### 查看所有定时计划

左侧「定时计划」列表显示所有已创建的定时计划及其执行时间。

### 编辑定时计划

选中一个计划 → 点击「编辑定时」→ 修改参数 → 点击「更新计划」。

### 删除定时计划

选中一个计划 → 点击「删除定时」→ 确认删除。

> [!CAUTION]
> 删除定时计划不会删除关联的测试计划或测试用例。

---

## 步骤 4：自动执行

当系统时间达到定时计划的执行时间时：

1. SchedulerService 触发计划
2. 自动调用 `PythonTestService.runTests()` 启动测试
3. 通过 IPC 事件 `scheduled-test-start` 通知前端更新 UI 状态
4. 测试日志实时输出到右侧面板
5. 测试完成后生成 Allure 报告

---

## 步骤 5：循环执行与失败处理

在创建测试计划时，可配置循环执行参数：

| 参数 | 说明 | 默认值 |
|------|------|--------|
| **循环次数** | 整个测试计划的循环执行次数 | 1（不循环） |
| **失败后继续** | 某次循环失败后是否继续执行后续循环 | 是 |

### 循环执行示例

```
循环次数: 3, 失败后继续: ✅
─────────────────────────
第1轮 → 执行 → 通过 ✓
第2轮 → 执行 → 失败 ✗ → 继续
第3轮 → 执行 → 通过 ✓
结果: 2/3 通过
```

```
循环次数: 3, 失败后继续: ❌
─────────────────────────
第1轮 → 执行 → 通过 ✓
第2轮 → 执行 → 失败 ✗ → 停止
结果: 1/2 通过 (第3轮未执行)
```

---

## 冲突检查

当保存定时计划时，系统会检查与新计划执行时间冲突的已有计划：

- 如果存在时间重叠的定时计划，弹出警告提示
- 确认后仍然可以保存（平台允许同时执行多个计划）

---

## 防睡眠模式

定时执行期间，如果启用「设置 → 运行 → 程序运行时禁用睡眠模式」，系统将在执行期间阻止 Windows 进入睡眠/休眠状态。

详见 [07 - 系统设置](07-settings.md)。

---

## 定时计划数据结构

`config/scheduled_plans.json` 示例：

```json
{
  "plans": [
    {
      "id": "sched_001",
      "name": "每日冒烟测试",
      "executeTime": "2026-05-08T08:00:00",
      "testPlanIds": ["plan_001"],
      "createdAt": "2026-05-07T16:00:00"
    }
  ]
}
```

---

## 限制

- 定时计划**仅支持单次执行**，不支持 cron 重复。如需每日执行，需每天创建或手动启动
- 定时计划执行时间以**本地系统时间**为准
- 计算机必须在执行时间点保持开机状态
